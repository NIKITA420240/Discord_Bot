# Discord Bot v2 — система учёта и контроля работы кураторов

Полнофункциональный Discord-бот для автоматического учёта работы кураторов, интеграции с Google Sheets и хранения истории в SQLite.  

Бот:

- напоминает кураторам отчитаться по количеству чатов;
- собирает сообщения и сохраняет их в базу;
- обновляет Google Sheets (статистика и рабочие часы);
- сверяет фактическую работу с расписанием;
- ищет «прогульщиков» и конфликтующие записи;
- даёт удобные команды для аналитики и проверки.

---

## 🔍 Краткий обзор

Основная идея:

1. Каждый час бот **напоминает** кураторам написать количество чатов.
2. Через несколько минут бот **собирает сообщения** за прошедший час.
3. Данные сохраняются в **SQLite** и одновременно пишутся в **две Google-таблицы**:
   - Статистика по часам;
   - Таблица рабочих часов.
4. Бот **сверяет** фактических работающих кураторов с расписанием:
   - ищет тех, кто был в графике, но **не сдал отчёт**;
   - фиксирует **конфликты записей** по рабочим часам.
5. Через команды можно:
   - смотреть статистику;
   - строить графики;
   - проверять смену и старшего;
   - находить прогульщиков.

Архитектура реализована в модулях `bot.py`, `collect.py`, `database.py`, `sheets.py`, `users.py`, `utils.py`.

## ⏱ Логика работы по времени

Основные константы (см. `utils.py`):   

- `Time_to_send = 55` — минута, когда бот напоминает кураторам писать количество чатов.
- `CHECK_MINUTES = 5` — минута, когда бот сравнивает расписание и фактических работающих.

Все внутренние расчёты привязаны к времени сервера и нормализуются к часовому поясу (UTC+3) внутри `bot.py`.   

### Цикл `periodic_task` (фоновая задача)

После запуска ивента `on_ready` в `bot.py` создаётся фоновая корутина `periodic_task()`, которая раз в минуту проверяет текущее время и выполняет три блока логики:   

1. **Напоминание кураторам (`Time_to_send` минут)**  
   - Если текущее время: `now.minute == Time_to_send`  
   - И в этом часу ещё не отправлялось напоминание (`bot.last_reminder_hour != now.hour`)  
   - И последнее сообщение в канале **не является** сообщением бота о чате  
   → Бот отправляет сообщение вида:
   > Пишите количество чатов за HH час. НЕ ПИШИТЕ в 55 МИНУТ!!!

2. **Сбор данных и запись в таблицы (минуты `5`)**  
   - Если `now.minute == 5` и данные за этот час ещё не собирались  
   - Вызывается `update_sheet(force_schedule_update=True)`:
     - из Discord берутся сообщения за последний час;
     - данные сохраняются в SQLite;
     - обновляются Google Sheets:
       - «Статистика»;
       - «Рабочие часы» (с записью фактически работающих кураторов и поиском конфликтов).

3. **Проверка прогульщиков (`CHECK_MINUTES` минут)**  
   - Если `now.minute == CHECK_MINUTES`  
   - Бот использует **последние собранные данные** (`bot.last_collected_data`) и функции из `sheets.py`, чтобы:   
     - получить список тех, кто должен был стоять в графике за прошедший час;
     - сравнить с теми, кто реально сдал отчёт;
     - найти «прогульщиков» (в графике есть, отчёта нет);
     - отправить уведомление в лог-канал (если он настроен).

## 📋 Команды бота

Ниже перечислены все основные команды, реализованные в `bot.py`. Некоторым командам требуется роль старшего куратора или администратора.   

### 1. Базовые команды

#### `!обнови`
**Роли:** `Старший куратор`, `Admin`, `Administrator`  
**Назначение:** принудительно собрать данные и обновить обе Google-таблицы.

Что делает:

1. Считывает последние сообщения из рабочего канала.
2. Сохраняет данные в SQLite.
3. Обновляет:
   - дневной лист статистики;
   - недельный лист рабочих часов (с учётом конфликтов).
4. Обновляет внутренний кэш `bot.last_collection_hour` и `bot.last_collected_data`, чтобы команды проверки (`!тест_прогул`) могли работать без ожидания автоматического цикла.

---

#### `!покажи`
**Роли:** любая  
**Назначение:** показать **последние собранные данные** за час.

Выводит список вида:

- Имя куратора, дата, час, количество чатов.

---

#### `!проверить`
**Роли:** любая  
**Назначение:** проверить, является ли **последнее сообщение в канале** сообщением бота или пользователя.

Используется для отладки и для логики «напоминания», чтобы бот не дублировал своё сообщение, если кто-то уже пишет про чаты.

---

### 2. Команды работы с БД и аналитикой

#### `!статистика`
**Роли:** любая  
**Назначение:** показать общую статистику по базе данных.

Показывается:

- общее количество записей;
- количество уникальных кураторов;
- дата первой записи;
- дата последней записи.

Данные берутся из `DatabaseManager.get_database_stats()`.   

---

#### `!топдетей [дни]`
**Роли:** любая  
**Назначение:** топ кураторов по **количеству чатов (детей)** за период.

- Аргумент `дни` (по умолчанию 7), максимум 30.
- Используется `collector.get_top_curators_count_sms(days, 10)` — суммарное количество чатов за период.   

---

#### `!топ [дни]`
**Роли:** любая  
**Назначение:** топ кураторов по **количеству рабочих часов** за период.

- Аргумент `дни` (по умолчанию 7), максимум 30.
- Используется `get_top_curators_count_hours`, где количество часов считается по количеству записей в БД (одна запись — один рабочий час), при этом учитываются только значения чатов в диапазоне `[-1; 40]`.   

---

#### `!история [ФИО] [дни]`
**Роли:** любая  
**Назначение:** показать историю работы конкретного куратора.

- Имя куратора передаётся текстом.
- Параметр `дни` — глубина истории (по умолчанию 7, максимум 30).
- Выводятся последние записи: дата, час, количество чатов.

---

#### `!последние [k]`
**Роли:** любая  
**Назначение:** показать **последние `k` сообщений** из базы данных (по полю `created_at`).

- Параметр `k` по умолчанию 10, максимум 50.
- Для каждого сообщения выводится:
  - ФИО куратора,
  - дата и час,
  - количество чатов.
- Команда учитывает лимит длины сообщения Discord и при необходимости разбивает ответ на несколько частей.

---

#### `!график`
**Роли:** любая  
**Назначение:** построить **график среднего количества чатов по часам**.

- Использует `DatabaseManager.get_avg_chats_for_hour()`, который считает среднее количество чатов для каждого часа суток.   
- График строится с помощью matplotlib, сохраняется в файл и отправляется как картинка в Discord.

---

#### `!очистить [дни]`
**Роли:** `старший куратор`, `Admin`, `Administrator`  
**Назначение:** удалить из БД записи старше указанного количества дней.

- Минимально допустимый период: 30 дней.
- Использует `delete_old_records(days)` в `DatabaseManager`, удаляя записи с `message_date` старше заданной границы.

### 3. Команды проверки расписания и смен

#### `!тест_прогул`
**Роли:** `Старший куратор`, `Admin`, `Administrator`  
**Назначение:** вручную запустить алгоритм поиска «прогульщиков» так же, как это делается автоматически в минуту `CHECK_MINUTES`.

Логика:

1. Проверяется, есть ли в памяти `bot.last_collected_data`.  
   Если данных нет — бот просит сначала выполнить `!обнови` или дождаться автоматического сбора.
2. Определяется текущий час и соответствующий ему слот в расписании.
3. Из Google Sheets берётся список тех, кто **должен работать** в этот час (`get_scheduled_workers`).
4. Список реально отчитавшихся берётся из ключей `bot.last_collected_data`.
5. Имена нормализуются (см. раздел про нормализацию имён), сравниваются, и формируется список «прогульщиков».
6. В канал выводится:
   - кто стоял в графике;
   - кто прислал чаты;
   - список прогульщиков (с дискорд-меншенами, если удаётся найти логин по имени).

---

#### `!смена`
**Роли:** `Старший куратор`, `Admin`, `Administrator`  
**Назначение:** показать список всех кураторов, записанных в **расписание на текущий час**.

Логика:

1. Текущее время переводится в формат расписания.
2. Через `get_scheduled_workers` из `sheets.py` берётся список людей, стоящих в графике.   
3. Для каждого имени подбирается Discord-меншен через `get_login_by_name` и поиск по участникам сервера.   

---

Логика:

1. Через `get_senior_for_hour` определяет_
